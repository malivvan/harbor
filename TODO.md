# Proposed Improvements

## Review scope

This proposal reviews the public APIs and implementation of the root package,
`db`, `fs`, `ts`, `vec`, `consensus`, and vendored/internal components. It is
based on repository structure, implementation review, API/docs comparison, and
the passing baseline `go test -count=1 -timeout 180s ./...` suite.

Usefulness scores are from 1 to 10:

- **9-10:** High impact, broadly useful or likely to prevent correctness/data-divergence defects.
- **7-8:** Strong improvement for important workflows or performance.
- **5-6:** Useful ergonomic, diagnostic, or maintainability enhancement.

## Ranked proposals

| Rank | Area | Proposal | Useful | Description |
|---:|---|---|---:|---|
| ~~1~~ | ~~Consensus + TS~~ | ~~Make replicated retention deterministic~~ | ~~**10**~~ | **DONE** — `ts.Series.InsertAt`/`InsertManyAt` take an explicit retention reference time; the leader pins its clock into the replicated `tsInsertArg`/`tsInsertManyArg` (`Now`), and the FSM applies it, so every replica prunes identically. `consensus.Node.SetNow` overrides the clock for tests. Regression tests: `TestReplicatedRetentionIsDeterministic`, `TestReplicatedRetentionPrunesIdentically`. |
| ~~2~~ | ~~Consensus~~ | ~~Replace apply panics with structured failures~~ | ~~**9**~~ | **DONE** — the FSM no longer panics on a corrupt, unknown, or malformed log entry. `Apply` returns an exported `consensus.ApplyError{Index, Op, Err}` (with `Unwrap`), `decodeArg` replaces `mustDecode`, unknown ops report the op name, and panic recovery remains as an outer safety net that logs the index. Regression test: `TestApplyErrorsAreStructured`. |
| ~~3~~ | ~~Observability~~ | ~~Add production metrics and tracing hooks~~ | ~~**9**~~ | **DONE** — new dependency-free `metrics` package defines an `Observer` interface (`Counter`/`Histogram`/`Gauge`/`StartSpan`) plus a `Nop` implementation, nil-safe helpers and the exported metric-name/label constants. It is plumbed through `harbor.Options.Metrics`, the four sub-store `Config`s and `consensus.Config`. Instrumented: bbolt transaction latency/outcome (db), FS chunk bytes/ops and inode-cache lookups/size, TS decode/aggregate duration, vec search duration/candidates and flush duration, key-rotation duration, and consensus apply lag. A nil observer costs one nil check. Tests: `metrics/metrics_test.go`. |
| ~~4~~ | ~~FS~~ | ~~Fix bounded inode-cache eviction~~ | ~~**8**~~ | **DONE** — policy: the cache never exceeds `maxSize`. `evictOldest` no longer skips dirty entries (safe because the store persists inodes synchronously, so a dropped entry is just re-read from disk), and `Put` only evicts when inserting a *new* inode, so re-putting an existing one no longer evicts an unrelated entry. Replaced the stale `TestInodeCache_NoDirtyEviction` with `TestInodeCache_EvictsDirtyWhenFull` and added `TestInodeCache_PutExistingDoesNotEvict`. |
| ~~5~~ | ~~FS~~ | ~~Batch and bound chunk deletions~~ | ~~**9**~~ | **DONE** — `truncateData`, `deleteAllChunks` and `writeAllChunks` no longer copy every matching key into memory. A shared `fsBucket.deleteChunks` helper deletes during cursor iteration (using `Cursor.Delete`), so removing a file with O(chunks) chunks no longer allocates O(chunks) key slices. Regression test `TestDeleteChunksMany` covers rewriting and deleting a 32-chunk file. |
| ~~6~~ | ~~FS~~ | ~~Add chunk read/write fast paths and prefetch~~ | ~~**8**~~ | **DONE** — `writeDataRange` detects a write that covers a whole chunk and writes it directly, skipping the decrypt + re-encrypt of the old chunk. `readDataRange` walks the inode's chunks with one cursor (one seek, then forward `Next`), instead of a separate `Get` per chunk, so a sequential read no longer does O(chunks) B-tree lookups. Regression test `TestFullChunkOverwriteFastPath`; the existing random-access, truncate and tamper tests still pass. |
| ~~7~~ | ~~FS~~ | ~~Add context and backpressure to `FastWalk`~~ | ~~**8**~~ | **DONE** — `FastWalkConfig` gains `Ctx` (cancellation-aware traversal, checked at the dispatch loop, the worker loop and per directory entry), `QueueSize` (bounds both internal channels so a slow callback applies backpressure) and `Metrics` (queue-depth gauge and callback-latency histogram). Added `FastWalkContext` as a convenience wrapper. Tests: `TestFastWalkCancelled`, `TestFastWalkCancelledDuringCallback`. |
| ~~8~~ | ~~FS~~ | ~~Optimize inode-cache hot reads~~ | ~~**7**~~ | **DONE** — a cache hit no longer takes the write lock or calls `time.Now()`. `hits`/`misses` are `atomic.Uint64`, and each entry's recency is a logical tick (`atomic.Uint64` from a cache-level counter), so `Get`/`GetShared` update atomics on the read path and `evictOldest` compares ticks. Mutation-copy safety (returned nodes are still copies) and the `CacheStats` surface are unchanged. Verified with `-race`. |
| ~~9~~ | ~~TS~~ | ~~Add persisted-series enumeration~~ | ~~**9**~~ | **DONE** — added `Store.ListSeries(ctx) ([]SeriesInfo, error)` and `Store.ListSeriesNames(ctx)`. `ListSeries` scans the metadata bucket (skipping the marker/version records) and, when a Root is configured, the series buckets under it, so a series created by a plain Insert (no metadata record) is still found. Results are sorted by name and carry labels/retention/count. At the database root only metadata-backed series are returned, because unrelated top-level buckets cannot be told apart. Tests: `TestListSeries` (reopen + delete) and `TestListSeriesEncryptedNames`. |
| ~~10~~ | ~~TS~~ | ~~Add block summary metadata for aggregates~~ | ~~**8**~~ | **DONE** — each sealed block now begins with a summary (count, sum, min, max, first, last) before the point records, sealed in the same blob so tampering anywhere still fails authentication. `Aggregate` in block mode uses `scanBlocksAggregate`: a block wholly inside the range that does not cross an aggregate-window boundary is answered from its summary (no per-point parse/aggregate); otherwise its points are decoded and filtered, so results are identical. `aggregator.addBlockSummary` merges a summary into the current window. Tests: `TestBlockSummaryAggregatesMatchScan` (all functions × window sizes vs. a plaintext scan) and `TestBlockSummaryPersisted`; `TestBlockModeTamper` still passes. |
| ~~11~~ | ~~TS~~ | ~~Add reverse and streaming range APIs~~ | ~~**8**~~ | **DONE** — added `RangeOptions{Descending, Limit, Offset}`, `RangeWithOptions`, and `RangeEachWithOptions` (bounded streaming). `Range`/`RangeEach` are now zero-option wrappers, so existing callers are unchanged. Scanning was refactored into `scanRangeOrdered` → `scanBlocksOrdered`/`scanPlainOrdered`, which walk blocks or records forward or backward and stop early at the limit, in both plaintext and block mode. Negative limit/offset returns `ErrInvalidOptions`. Test: `TestRangeOptions`. |
| ~~12~~ | ~~TS~~ | ~~Optimize insertion grouping and append-only blocks~~ | ~~**7**~~ | **DONE** — `insertBlocks` takes a single-block fast path (skips the group map and start sort) and shares an `insertBlockBatch` helper for the grouped case. `mergePoints` skips the copy and sort for an already sorted, duplicate-free batch (`sortedUniqueByTimestamp`). `mergePoint` skips the binary search when the new point is newer than everything stored. Duplicate-timestamp last-wins and multi-block grouping are unchanged. Test: `TestInsertBlockFastPaths`. |
| ~~13~~ | ~~Vec~~ | ~~Add direct point retrieval APIs~~ | ~~**8**~~ | **DONE** — added `Collection.Get(id)` (reads the in-memory index, so it sees buffered upserts) and `Store.GetPoint(colName, id)` / `Store.GetPoints(colName, ids)` (durable bbolt view). `GetPoints` returns found points plus the missing IDs in request order, deduped. Added `ErrPointNotFound`; missing collections return `ErrCollectionNotFound`. `VectorIndex` gains `Get`, implemented by Flat, HNSW and the test mock. `LoadCollection` was refactored onto a shared `decodePointValue` helper (including dequantization). Tests: `TestGetPoint`, `TestGetPoints`. |
| ~~14~~ | ~~Vec~~ | ~~Add streaming/paginated filtered retrieval~~ | ~~**8**~~ | **DONE** — added `ListOptions{Offset, Limit}`, `Collection.ListPoints(filter, opts)` (stable ascending-ID order, materializes only the selected page) and `Collection.ForEachPoint(filter, fn)` (streams in stable ID order, one point at a time, stops on `ErrStopIteration`, propagates other errors). Sorting the matching IDs gives pagination a deterministic order independent of map iteration. Negative options and a nil callback return `ErrInvalidOptions`. Tests: `TestListPoints`, `TestForEachPoint`. |
| ~~15~~ | ~~Vec~~ | ~~Add a collection options API~~ | ~~**8**~~ | **DONE** — added `CollectionOptions{Name, VectorLen, Metric, UseHNSW, HNSWParams, FlushThreshold}` and `Store.NewCollectionWithOptions`. `resolve()` validates the name (required), positive dimension, and metric (Cosine/Euclid/Dot), normalizes HNSW params, and defaults `FlushThreshold` to `DefaultFlushThreshold`; the threshold is now a real per-collection knob. `NewCollection`/`NewCollectionWithParams` are thin wrappers over `NewCollectionWithOptions`. Quantization stays store-level and is documented as such. Tests: `TestNewCollectionWithOptions`, `TestNewCollectionWithOptionsValidation`. |
| ~~16~~ | ~~Vec~~ | ~~Improve filtered HNSW search fallback~~ | ~~**8**~~ | **DONE** — filtered `Search` no longer does a single fixed over-fetch (`topK*10`) then a full scan. It starts at `topK*4` and grows the candidate fetch geometrically, doubling until it has `topK` matches or reaches the whole index; only then does it fall back to the exact scan, preserving Flat-index semantics when the graph cannot prove enough matches. The index now takes the store's metrics observer and reports `MetricVecFallbacks` and `MetricVecScanSize` (sparse-filter diagnostic) on each fallback. Test: `TestHNSWFilteredSearchFallback` (unique/rare/absent filters are exact; fallback counter increments). |
| 17 | Vec | Optimize distance kernels | **7** | Scalar distance loops and public Euclidean square roots can dominate hot search paths. Use squared Euclidean distance internally, cache or normalize applicable norms, and provide optional architecture-specific SIMD kernels with portable fallbacks. Primary file: `vec/math.go`. |
| 18 | Vec | Reduce HNSW read-lock scope | **7** | Searches hold the HNSW read lock through graph traversal, sorting, filtering, and payload cloning. Snapshot immutable candidate metadata first, then perform payload clones and ranking outside the long lock. This improves concurrent search/upsert behavior. Primary file: `vec/hnsw_index.go`. |
| 19 | DB | Add context-aware streaming query results | **8** | `Find` materializes results and callback APIs are difficult to compose. Add an exported iterator or typed stream with `Next`, `Key`, `Value`, and `Err`, so large scans can stream and cancel correctly. Primary file: `db/query.go`. |
| 20 | DB | Make query builders immutable or cloneable | **7** | Methods such as `Limit`, `Skip`, `OrderBy`, and `First` mutate reusable query objects. Add immutable builder methods or `Clone()`/copy-on-write behavior to prevent accidental reuse and hidden state changes. Primary file: `db/query.go`. |
| 21 | FS | Export a public external-content interface | **8** | `OpenWithContentFS` accepts a module-internal `absfs.FileSystem`, making the writable external-content extension unavailable cleanly to external module users. Export a public `ContentFS` interface (or accept a documented standard-FS plus write extension) and keep absfs details internal. Primary file: `fs/store.go`. |
| 22 | FS | Add `CopyOptions` and context-aware copying | **7** | `Copy` has no overwrite policy, metadata/symlink controls, progress reporting, or context cancellation. Add options and a context variant while retaining the existing method for compatibility. Primary file: `fs/fs.go`. |
| 23 | Root | Add consistent backup/export APIs | **8** | Root operations expose raw bbolt access but no stable, high-level backup snapshot API. Add `Backup(ctx, writer)`, `CopyTo`, or `Snapshot` helpers that coordinate vec flushing, active writes, ownership, and close state and document whether the result is encrypted. Primary file: `harbor.go`. |
| 24 | Consensus | Widen replicated mutation coverage | **8** | The current consensus facades cover only selected db/TS/vec/fs operations. Add db raw KV writes, streaming FS writes/opens, richer vec flush/config operations, and TS range deletion/metadata parity. This should be data-driven by the complete public store API and command coverage tests. Primary files: `consensus/db.go`, `consensus/fs.go`, `consensus/ts.go`, `consensus/vec.go`. |
| 25 | Package-wide | Make vector flush and ownership behavior ergonomic | **7** | Vector writes can remain in memory until the threshold or `Flush`, and sub-store `Close` behavior differs from root ownership. Add explicit collection/store lifecycle options, clearer flush/closed states, and examples for shared handles and root-store embedding. Primary files: `vec/collection.go`, `vec/store.go`, `harbor.go`. |
| 26 | Package-wide | Add benchmark matrices for real workloads | **7** | Existing benchmarks cover core operations but omit encrypted overhead, filtered vector search, chunked FS I/O, FastWalk, TS aggregate/retention, cache hit rates, and S3 multipart behavior. Add pinned workload matrices and regression thresholds to CI rather than isolated happy-path benchmarks. Primary files: package `bench_test.go` files and `.github/workflows/ci.yml`. |
| 27 | Package-wide | Define and expose configuration validation centrally | **7** | Several package constructors use positional parameters or separate validation paths. Add reusable options with constructors and `Validate()` methods for DB codecs, FS chunk sizes, TS block durations, vec dimensions/index parameters, and root encryption flags. Provide an internal normalization step to prevent config drift. Primary files: package `store.go` and `*config.go` implementations. |
| 28 | Package-wide | Add a migration and compaction toolkit | **6** | A format or encryption migration can be made only by export/re-import today. Add versioned export/import, record-level progress, checksum verification, compaction/rewriting, and dry-run validation while preserving fail-closed compatibility behavior. Primary files: package version/rotation implementations and root package. |

## Highest-priority implementation sequence

1. Fix consensus retention determinism, malformed apply handling, and write coverage.
2. Correct the FS inode cache bound and chunk deletion memory behavior.
3. Improve TS persisted enumeration and block/aggregate performance.
4. Add direct, streaming, and paginated vector and DB APIs.
5. Add package metrics, benchmark matrices, and backup/export tooling.
