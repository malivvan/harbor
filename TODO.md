# Proposed Improvements

## Review scope

This proposal reviews the public APIs and implementation of the root package,
`db`, `fs`, `ts`, `vec`, `consensus`, and vendored/internal components. It is
based on repository structure, implementation review, API/docs comparison, and
the passing baseline `go test -count=1 -timeout 180s ./...` suite.

Usefulness scores are from 1 to 10:

- **9-10:** High impact, broadly useful or likely to prevent correctness/data-divergence defects.
- **7-8:** Strong improvement for important workflows or performance.
- **5-6:** Useful ergonomic, diagnostic, or maintainability enhancement.

## Ranked proposals

| Rank | Area | Proposal | Useful | Description |
|---:|---|---|---:|---|
| ~~1~~ | ~~Consensus + TS~~ | ~~Make replicated retention deterministic~~ | ~~**10**~~ | **DONE** — `ts.Series.InsertAt`/`InsertManyAt` take an explicit retention reference time; the leader pins its clock into the replicated `tsInsertArg`/`tsInsertManyArg` (`Now`), and the FSM applies it, so every replica prunes identically. `consensus.Node.SetNow` overrides the clock for tests. Regression tests: `TestReplicatedRetentionIsDeterministic`, `TestReplicatedRetentionPrunesIdentically`. |
| ~~2~~ | ~~Consensus~~ | ~~Replace apply panics with structured failures~~ | ~~**9**~~ | **DONE** — the FSM no longer panics on a corrupt, unknown, or malformed log entry. `Apply` returns an exported `consensus.ApplyError{Index, Op, Err}` (with `Unwrap`), `decodeArg` replaces `mustDecode`, unknown ops report the op name, and panic recovery remains as an outer safety net that logs the index. Regression test: `TestApplyErrorsAreStructured`. |
| ~~3~~ | ~~Observability~~ | ~~Add production metrics and tracing hooks~~ | ~~**9**~~ | **DONE** — new dependency-free `metrics` package defines an `Observer` interface (`Counter`/`Histogram`/`Gauge`/`StartSpan`) plus a `Nop` implementation, nil-safe helpers and the exported metric-name/label constants. It is plumbed through `harbor.Options.Metrics`, the four sub-store `Config`s and `consensus.Config`. Instrumented: bbolt transaction latency/outcome (db), FS chunk bytes/ops and inode-cache lookups/size, TS decode/aggregate duration, vec search duration/candidates and flush duration, key-rotation duration, and consensus apply lag. A nil observer costs one nil check. Tests: `metrics/metrics_test.go`. |
| 4 | FS | Fix bounded inode-cache eviction | **8** | `Put` may exceed `maxSize` when every cached entry is dirty because `evictOldest` skips dirty entries and the new entry is still inserted. Define and test one policy: evict dirty entries after a bounded flush, reject/cache-miss when full, or enforce a separate dirty-entry bound. Primary file: `fs/cache.go`. |
| 5 | FS | Batch and bound chunk deletions | **9** | Chunk truncation and inode deletion copy every matching chunk key into memory before deleting it. Iterate with bounded batches or carefully delete during cursor iteration, so very large files do not temporarily consume O(chunks) memory. Primary file: `fs/chunk.go`. |
| 6 | FS | Add chunk read/write fast paths and prefetch | **8** | Full-chunk writes currently decrypt and re-encrypt the existing chunk even when the input replaces the entire chunk. Add full-chunk overwrite detection, and for reads add bounded sequential prefetch or an incremental reader. This should improve large chunked-file throughput without whole-file materialization. Primary file: `fs/chunk.go`. |
| 7 | FS | Add context and backpressure to `FastWalk` | **8** | `FastWalk` uses fixed CPU-count worker fan-out and entry callbacks without a caller context. Add cancellation-aware traversal, configurable worker/queue limits, and metrics for queue depth and callback latency so remote or slow backends cannot oversubscribe resources. Primary files: `fs/fastwalk.go`, `fs/walk.go`. |
| 8 | FS | Optimize inode-cache hot reads | **7** | Cache hits perform a write-lock acquisition and call `time.Now()` even though the LRU/clock state is only approximate. Use sampling, epoch counters, or atomic access metadata for hits, while preserving mutation-copy safety and cache statistics. Primary file: `fs/cache.go`. |
| 9 | TS | Add persisted-series enumeration | **9** | `SeriesNames` only returns names seen in the current process instance, while reopened stores should be able to list persisted series. Add `ListSeries(ctx)` (or equivalent) that scans metadata and data buckets and returns stable sorted or creation-ordered names. Optionally include labels and retention metadata in the result. Primary file: `ts/store.go`. |
| 10 | TS | Add block summary metadata for aggregates | **8** | Common aggregates decode and process every point. Persist block summaries containing count, sum, min, max, first, and last, then use them for compatible aggregate requests while retaining exact point scans for unsupported functions or old blocks. Primary files: `ts/block.go`, `ts/aggregate.go`. |
| 11 | TS | Add reverse and streaming range APIs | **8** | `Range` materializes ascending point slices and `RangeEach` has no reverse, limit, or offset controls. Add a `RangeOptions` API for descending order, limit/offset, and bounded streaming, and keep existing methods compatible. Primary file: `ts/series.go`. |
| 12 | TS | Optimize insertion grouping and append-only blocks | **7** | `InsertMany` can build maps and sort blocks even for a single block or already-sorted input. Add fast paths for append-only, single-block, and sorted batches, reducing allocations and CPU on common time-series workloads. Primary files: `ts/block.go`, `ts/series.go`. |
| 13 | Vec | Add direct point retrieval APIs | **8** | There is no obvious `Get(id)` or `GetMany(ids)` surface, although search, filter retrieval, and deletion are available. Add direct retrieval with explicit not-found behavior and perhaps a batch result that preserves found/missing IDs. Primary files: `vec/collection.go`, `vec/store.go`. |
| 14 | Vec | Add streaming/paginated filtered retrieval | **8** | Search and filter retrieval materialize all or many results. Add limit-aware iterators or callback APIs with stable ordering and stop-on-error behavior. This is valuable for large filtered result sets and for database-style pagination. Primary files: `vec/collection.go`, `vec/hnsw_index.go`, `vec/flat_index.go`. |
| 15 | Vec | Add a collection options API | **8** | Collection construction currently uses positional arguments and separate HNSW/quantization/flush concepts. Introduce `CollectionOptions` with validated dimensions, metric, index parameters, quantization behavior, and flush threshold, while retaining existing constructors as wrappers. Primary file: `vec/collection.go`. |
| 16 | Vec | Improve filtered HNSW search fallback | **8** | Filtered HNSW search over-fetches, then may fall back to exact scanning of every point. Add adaptive `efSearch` and filter-aware candidate expansion, including sparse-filter and fallback diagnostics. Preserve exact semantics when the graph cannot prove enough matches. Primary file: `vec/hnsw_index.go`. |
| 17 | Vec | Optimize distance kernels | **7** | Scalar distance loops and public Euclidean square roots can dominate hot search paths. Use squared Euclidean distance internally, cache or normalize applicable norms, and provide optional architecture-specific SIMD kernels with portable fallbacks. Primary file: `vec/math.go`. |
| 18 | Vec | Reduce HNSW read-lock scope | **7** | Searches hold the HNSW read lock through graph traversal, sorting, filtering, and payload cloning. Snapshot immutable candidate metadata first, then perform payload clones and ranking outside the long lock. This improves concurrent search/upsert behavior. Primary file: `vec/hnsw_index.go`. |
| 19 | DB | Add context-aware streaming query results | **8** | `Find` materializes results and callback APIs are difficult to compose. Add an exported iterator or typed stream with `Next`, `Key`, `Value`, and `Err`, so large scans can stream and cancel correctly. Primary file: `db/query.go`. |
| 20 | DB | Make query builders immutable or cloneable | **7** | Methods such as `Limit`, `Skip`, `OrderBy`, and `First` mutate reusable query objects. Add immutable builder methods or `Clone()`/copy-on-write behavior to prevent accidental reuse and hidden state changes. Primary file: `db/query.go`. |
| 21 | FS | Export a public external-content interface | **8** | `OpenWithContentFS` accepts a module-internal `absfs.FileSystem`, making the writable external-content extension unavailable cleanly to external module users. Export a public `ContentFS` interface (or accept a documented standard-FS plus write extension) and keep absfs details internal. Primary file: `fs/store.go`. |
| 22 | FS | Add `CopyOptions` and context-aware copying | **7** | `Copy` has no overwrite policy, metadata/symlink controls, progress reporting, or context cancellation. Add options and a context variant while retaining the existing method for compatibility. Primary file: `fs/fs.go`. |
| 23 | Root | Add consistent backup/export APIs | **8** | Root operations expose raw bbolt access but no stable, high-level backup snapshot API. Add `Backup(ctx, writer)`, `CopyTo`, or `Snapshot` helpers that coordinate vec flushing, active writes, ownership, and close state and document whether the result is encrypted. Primary file: `harbor.go`. |
| 24 | Consensus | Widen replicated mutation coverage | **8** | The current consensus facades cover only selected db/TS/vec/fs operations. Add db raw KV writes, streaming FS writes/opens, richer vec flush/config operations, and TS range deletion/metadata parity. This should be data-driven by the complete public store API and command coverage tests. Primary files: `consensus/db.go`, `consensus/fs.go`, `consensus/ts.go`, `consensus/vec.go`. |
| 25 | Package-wide | Make vector flush and ownership behavior ergonomic | **7** | Vector writes can remain in memory until the threshold or `Flush`, and sub-store `Close` behavior differs from root ownership. Add explicit collection/store lifecycle options, clearer flush/closed states, and examples for shared handles and root-store embedding. Primary files: `vec/collection.go`, `vec/store.go`, `harbor.go`. |
| 26 | Package-wide | Add benchmark matrices for real workloads | **7** | Existing benchmarks cover core operations but omit encrypted overhead, filtered vector search, chunked FS I/O, FastWalk, TS aggregate/retention, cache hit rates, and S3 multipart behavior. Add pinned workload matrices and regression thresholds to CI rather than isolated happy-path benchmarks. Primary files: package `bench_test.go` files and `.github/workflows/ci.yml`. |
| 27 | Package-wide | Define and expose configuration validation centrally | **7** | Several package constructors use positional parameters or separate validation paths. Add reusable options with constructors and `Validate()` methods for DB codecs, FS chunk sizes, TS block durations, vec dimensions/index parameters, and root encryption flags. Provide an internal normalization step to prevent config drift. Primary files: package `store.go` and `*config.go` implementations. |
| 28 | Package-wide | Add a migration and compaction toolkit | **6** | A format or encryption migration can be made only by export/re-import today. Add versioned export/import, record-level progress, checksum verification, compaction/rewriting, and dry-run validation while preserving fail-closed compatibility behavior. Primary files: package version/rotation implementations and root package. |

## Highest-priority implementation sequence

1. Fix consensus retention determinism, malformed apply handling, and write coverage.
2. Correct the FS inode cache bound and chunk deletion memory behavior.
3. Improve TS persisted enumeration and block/aggregate performance.
4. Add direct, streaming, and paginated vector and DB APIs.
5. Add package metrics, benchmark matrices, and backup/export tooling.
